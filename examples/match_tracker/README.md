# match_tracker

Reference app for stratastax-flutter, on the real bundled contracts of stratastax-contract
(platform and catalog) and the brand tokens of stratastax-design. Both are fetched from
[docs.stratastax.dev](https://docs.stratastax.dev/) and pinned in `stx.lock`. To build against
local checkouts, override the source in a `stx.local.yaml` (see docs/ARCHITECTURE.md §3).

Hand-written: `stx.yaml`, `stx.tokens.yaml`, `i18n/*.yaml` and the annotated classes in
`lib/features/`. Everything in `lib/gen/` is generated by `stx build`:

| Directory | From |
|---|---|
| `lib/gen/contract` | the OpenAPI contracts: models, codecs, validation, endpoints, scopes |
| `lib/gen/style` | `stx.tokens.yaml` + the brand layer + stx_style defaults |
| `lib/gen/i18n` | `i18n/*.yaml` + stx_i18n framework texts |
| `lib/gen/app` | the annotations: forms, overviews, pages, mappers, routes, services, app |

## Demo

```sh
tool/demo.sh   # from the repository root: stub server, stx watch and the app in Chrome
```

Then, at http://localhost:8085:

1. **Sign in.** The stub's identity provider offers three users (or use *Sign in with Google* /
   *GitHub*, which go straight to `player` / `admin`):

   | User | Can |
   |---|---|
   | Ada Admin (`admin`) | everything: *New game* and *New match* |
   | Pim Player (`player`) | browse, record matches; *Games* has no *New game* button |
   | Vera Viewer (`viewer`) | browse only: no *New* buttons; `/matches/new` opened directly says *You don't have access to this page* |

2. **Browse** (`lib/features/*/…_overview.dart`): the app opens on *Matches*, 45 seeded matches,
   newest first, with a side panel of filters. Type *cat* in *Search*, pick a game, set a period,
   or sort by clicking a column header; *Next* and *Previous* follow the cursors of the contract
   and *1–20 of 45* comes from `/matches/count`. *Games* uses `layout: auto`: a side panel on a
   wide window, a bar above the table below 1024 px. Make the window narrow: the table becomes cards and the
   filters move behind a *Filters* button. Every request is in the stub's log, e.g.
   `GET /api/v1/matches?limit=20&filter=gameId%3D%3D…&sort=playedAt%3ADESC`.
3. **Record a match** as Pim: search a game (*cat* → Catan), *Now*, add two players (*cha*, *bo*),
   mark a winner, *Save*. The stub validates the request against the contract and stores it.
   Back in *Matches* it is on top, *1–20 of 46*: the save dropped the cached pages of `matches`.
4. **Switch to Dutch**: the title becomes *Partijen* and the player count *Nog niemand*. Those
   texts are not in `i18n/nl.yaml`; the stub publishes them as the i18n CMS would. The app shows
   its YAML texts first and swaps the published ones in once they arrive, fetched with its own
   service account (`backends.i18n`, `i18n.remote` in `stx.yaml`), not with your login.
5. **Change something** while it runs: a text in `i18n/nl.yaml`, a rule in
   `@UiFieldValidate`, a colour in `stx.tokens.yaml`. `stx watch` regenerates only what changed;
   press `r` for a hot reload.
6. **Look inside**: `dart run stx_compiler:stx scan` prints the merged IR: per form the route,
   the operation and backend it submits to, the scopes the page needs, and per field the contract
   property, the merged rules and the translation keys.

## Commands

```sh
dart run stx_compiler:stx build      # regenerate lib/gen
dart run stx_compiler:stx watch      # … and again on every change
dart run stx_compiler:stx scan       # the merged IR as YAML (--contracts: also the full contract IR)
dart run stx_compiler:stx i18n sync  # add the translation keys new fields need
dart run stx_compiler:stx sources update  # fetch new contract/token versions, update stx.lock
flutter test                         # incl. end to end against the stub server (test/e2e_test.dart)
```

The base URLs come from `stx.yaml` `backends` and can be overridden with
`--dart-define=STX_PLATFORM_BASE_URL=…` / `STX_CATALOG_BASE_URL=…`; the identity provider with
`--dart-define=STX_OIDC_ISSUER=https://…/realms/stratastax` (e.g. a real Keycloak).

The tokens are the Stratastax brand layer: shadcn calm with indigo primary, teal secondary and
success, and coral accents. `stx.tokens.yaml` only adds what is specific to the app: the `win`
colour and button, and `loss`.
