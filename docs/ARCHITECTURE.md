## 0. Overview

stratastax-flutter is an annotation- and contract-driven Flutter framework. The `stx` compiler
reads a set of inputs, merges them into one model and generates the boilerplate of an app: models,
validation, endpoints, scopes, forms, pages, routes, dependency wiring and guards. The runtime
packages it generates against are built only on `flutter/widgets.dart` and are fully tokenized.

| Input | Provides |
|---|---|
| OpenAPI contract(s), local or remote (pinned in `stx.lock`) | Models, validation, endpoints, scopes |
| `stx.tokens.yaml`, optionally on a brand layer (`tokens.base`) | Design tokens |
| `i18n/*.yaml` | All texts |
| Annotated Dart classes in `lib/` | Forms, overviews, pages, routes, data sources, custom fields |
| `stx.yaml` | Configuration: backends, contracts, security, output |

The generated code ends up in `lib/gen/` of the consuming app.

---

## 1. Principles

1. **Contract first.** OpenAPI determines the DTOs, the validation, the endpoints and the scopes.
   The UI can only tighten rules, never loosen them. Loosening is a build error.
2. **Annotation → IR → render.** Nothing ever goes directly from YAML to widget code. Every source
   first becomes an IR. The IRs are merged and validated, and only then does the compiler render.
3. **Nothing is discovered at runtime.** There is no reflection and no registration at startup:
   - routing is a generated `switch` on path segments
   - validation is straight-line code
   - a permission check compares a const set of `Scope` enums with the scopes of the token
   - translations are in const tables per locale, by key name
4. **Styling only through tokens, text only through keys.**
   - Widgets accept `ColorToken`, `SpaceToken`, `TextToken` and `ButtonVariant`, never
     `Color`, `EdgeInsets` or `TextStyle`.
   - Text is passed as `Msg`, never as `String`.
   - Lints enforce this in handwritten code.
5. **Deterministic.** Output is sorted and stable. A file is only written when its content
   changes, so hot reload stays calm. Every file starts with
   `// Auto-generated by stratastax:codegen. Do not edit manually.`
6. **The build fails, the runtime does not.** See the list in [§12](#12-build-errors).

## 3. Compiler pipeline

```
                         ┌──────────────── phase 1: YAML sources ────────────────┐
  OpenAPI yaml(s) ──► ContractFrontend ──► ContractIR ─┐
  stx.tokens.yaml ──► StyleFrontend ─────► StyleIR ────┼─► validate ─► render lib/gen/contract/**
  i18n/*.yaml     ──► I18nFrontend ──────► I18nIR ─────┘              render lib/gen/style/**
                                                                       render lib/gen/i18n/**   (keys!)
                         └────────────────────────────────────────────────────────┘
                                  consumer code can now resolve against lib/gen
                         ┌──────────────── phase 2: Dart sources ────────────────┐
  lib/**.dart ──► AnnotationFrontend (analyzer, resolved AST) ──► UiIR
                                         │
                Merger: UiIR × ContractIR × StyleIR × I18nIR ──► AppIR
                                         │   • field ↔ contract-property correlation
                                         │   • merged validation (contract ∩ ui)
                                         │   • requiredScopes per page
                                         │   • required i18n keys
                Validators ──► diagnostics (file:line:col, code, hint)
                                         │
                Renderers ──► lib/gen/app/** (forms, pages, mappers, routes, services, app)
                         └────────────────────────────────────────────────────────┘
```

Phase 2 resolves against the output of phase 1, which is why the two phases run in this order.

### CLI

| Command | Does |
|---|---|
| `stx build` | Phase 1 and 2. Exit code ≠ 0 on errors. |
| `stx watch` | Builds, and again on every change that can affect the output (stx.yaml, stx.local.yaml, stx.lock, local contracts and tokens, `i18n/*.yaml`, `lib/**.dart` outside `lib/gen`), debounced. Only changed files are written, so hot reload sees exactly what changed. A rebuild takes ~4 s (mostly the analyzer). |
| `stx scan` | Dumps the IR as YAML: backends, security, per form the route/operation/backend/scopes and per field the contract property, merged rules and keys, datasources, mappers, and summaries of the contract, style and i18n IR. `--contracts` adds the full `ContractIR`. |
| `stx i18n sync` | Fills in missing keys (see §9). Never runs implicitly. |
| `stx sources update` | Fetches the latest version of every remote source, prints what changed (for a contract: `info.version` and the added and removed operations) and updates `stx.lock`. |

`--offline` (before the command: `stx --offline build`) only uses the cached remote sources.

### Reading annotations

`ElementAnnotation.computeConstantValue()` returns a fully typed `DartObject`. With it,
`@UiForm(submit: MatchesApiV1.createMatch)` can be resolved directly to the const `Endpoint` and
its `operationId`, and `@UiFieldWidget(PlayerPickerField)` can be resolved to a `ClassElement`
whose generic supertype we check. The compiler therefore works on resolved elements, not on names.

### IR model

```dart
// ContractIR
final class ContractIR { final Map<String, SchemaIR> schemas; final List<OperationIR> operations; final List<ScopeIR> scopes; }
final class SchemaIR { final String name; final List<PropertyIR> properties; final List<String> required; final SchemaKind kind; /* object | enum | array | alias */ }
final class PropertyIR { final String name; final TypeRefIR type; final bool nullable; final ConstraintIR constraints; final String? description; }
final class ConstraintIR { final int? minLength, maxLength, minItems, maxItems; final num? minimum, maximum; final String? pattern; final UiFormat? format; }
final class OperationIR { final String operationId, tag; final HttpMethod method; final PathTemplateIR path; final List<ParamIR> params; final TypeRefIR? body, response; final SecurityIR security; final bool idempotent; }
sealed class SecurityIR {}  // Public | Authenticated | Scopes(Set<String>) | Undeclared

// StyleIR
final class StyleIR { final List<String> modes; final Map<String, ColorValueIR> colors; final ScaleIR space, radius; final List<int> breakpoints; final Map<String, ResponsiveIR<TextSpecIR>> text; final Map<String, Map<String, ComponentVariantIR>> components; }

// I18nIR
final class I18nIR { final String base; final List<String> locales; final Map<String, MessageIR> messages; /* key → per-locale AST */ }
sealed class IcuNode {}     // Literal | Placeholder(type) | Plural | Select | DateFmt | NumberFmt

// UiIR
final class FormIR { final ClassRef model; final EndpointRef submit; final UiNavigate onSuccess; final List<FieldIR> fields; final RouteIR? route; }
final class FieldIR { final String name; final int order; final DartTypeRef type; final UiFieldKind kind; final MsgRef label; final MsgRef? hint, help; final DataSourceRef? dataSource; final ClassRef? widget; final ConverterRef? converter; final ConstraintIR uiConstraints; }
final class RouteIR { final String path; final List<RouteParamIR> params; final UiNav? nav; }
final class DataSourceIR { final ClassRef owner; final EndpointRef endpoint; final String query, value, label; }

// AppIR (after merge)
final class AppIR { final List<FormPlan> forms; final List<RoutePlan> routes; final List<DataSourcePlan> sources; final Set<String> requiredKeys; }
final class FormPlan { final FormIR form; final SchemaIR body; final List<FieldBinding> bindings; final List<List<String>> requires; }
final class FieldBinding { final FieldIR field; final PropertyIR? property; final ConstraintIR merged; final MapperIR mapper; }
```

### Remote sources

A file that stx.yaml refers to (`contracts.*.spec`, `tokens.file`, `tokens.base`) is one of:

- a path relative to the project;
- an `https://` URL;
- `<source>:<path>`, with `<source>` an alias from `sources:`; the path is resolved against its
  base, a URL or a local directory.

A remote file is fetched into `.dart_tool/stx/sources/<host>/<path>`, and the frontends read that
copy. They never see the network. `stx.lock` (committed) holds the sha256 of every remote file,
because docs.stratastax.dev always serves the latest version:

| Situation in a build | Result |
|---|---|
| Cached, and the hash matches the lock (or the file is not locked yet) | The cache, without the network |
| Not cached (a fresh checkout) | Fetched; the hash must match the lock (`STX-R002` otherwise) |
| Not locked yet | Fetched and added to `stx.lock` |
| `--offline` and not cached | `STX-R001` |

`stx.lock` only keeps the sources stx.yaml still uses; `stx scan` (a dry run) does not write it.
`stx sources update` accepts new versions.

To build against local checkouts (e.g. a contract change that is not published yet), override an
alias in `stx.local.yaml`. It is not committed and only accepts `sources:`:

```yaml
sources:
  stratastax: ../../../stratastax-docs/public   # after `npm run sync` there
```

A local source is not cached or locked. Diagnostics and generated headers show the reference as
written (`stratastax:openapi/…`), so the output does not change with an override.

## 4. Styling and tokens

The defaults follow shadcn/ui (zinc neutrals, radius 6, compact 14px UI text, headings with
negative letter spacing) and live in
[`stx_style/lib/defaults/defaults.tokens.yaml`](../packages/stx_style/lib/defaults/defaults.tokens.yaml).
An app overrides them in its own [`stx.tokens.yaml`](../examples/match_tracker/stx.tokens.yaml),
optionally on top of a brand layer (`tokens.base`). For Stratastax apps that layer is
[stratastax-design](https://github.com/buijs-dev/stratastax-design), published on
`https://docs.stratastax.dev/design/stratastax.tokens.yaml`. The brand layer sets every slot, so
the app only adds what is its own under `extend`.

What the build does:

1. The defaults, the brand layer and the app's `stx.tokens.yaml` are deep-merged (the upper
   layer wins per key).
2. References (`{palette.blue.700}`, also `{color.primary}`) are resolved per mode, with
   detection of unknown and cyclic refs (`STX-S001`).
3. Every slot must have a value and every value must be valid (`STX-S002`, with path).
4. The contrast of every `foreground`/`background` pair is checked per mode (`STX-S003`,
   warning below 4.5:1).
5. `lib/gen/style/tokens.g.dart` is rendered: `const stxTokensLight`/`stxTokensDark`, `AppColor` and
   `AppButton` for `extend`, and the const utilities `Gaps` (e.g. `Gaps.md`) and `Pad` (e.g.
   `Pad.xMdYSm`). The utilities work without a theme lookup because geometry is mode-independent.

Fixed slots in `stx_style`: 18 colors (`primary` … `transparent`), `SpaceToken`
(`none`…`x3l`), `RadiusToken`, `TextToken`, `Breakpoint`, and the buttons `primary`, `secondary`,
`danger`, `ghost`. App-specific tokens go through `color.extend` (id ≥ 32) and
`components.button.extend` (id ≥ 8) and are generated with `ColorToken.generated(id)`. That
constructor is public because generated code lives in the app; the lint `stx_no_generated_tokens`
restricts it to `lib/gen`.

### Format

- **Layering from W3C Design Tokens (DTCG):** primitives (palette, unit, fonts) → semantic
  (`color.primary`, `space.md`, `text.header1`) → component (`button.primary`, `field.error`).
  References are written as `{palette.indigo.600}`.
- **Scales from Tailwind:** spacing in multiples of a base unit of 4px, and
  breakpoint-keyed responsive values such as `size: { base: 28, lg: 36 }`.
- **Modes (light/dark) for colors only.** Geometry is mode-independent and therefore `const`.

### The contract between runtime and consumer

The runtime library is compiled before any consumer YAML exists. That is why `stx_style` fixes a
**schema of semantic slots**:

| Group | Slots |
|---|---|
| `color` | `primary`, `onPrimary`, `secondary`, `success`, `danger`, `onDanger`, `surface`, `onSurface`, `muted`, `border`, `transparent`, … (ids 0–31) |
| `space` | `none xs sm md lg xl x2l x3l` |
| `radius` | `none sm md lg full` |
| `text` | `header1 header2 header3 body label caption` |
| `components` | `button.{primary,secondary,danger,ghost}`, `field`, `focus`, `table` (header, rows, divider), `chip` (normal and selected), `panel` (the filter panel, incl. its width) |

- `stx_ui` uses only these slots.
- The YAML fills in values. Missing slots come from `stx_style/defaults.tokens.yaml`.
- Via `extend:` an app adds its own tokens. Colors get ids from 32, variants from their own
  offset. For these the compiler generates typed constants (`AppColor.win`).

### Runtime types

```dart
extension type const ColorToken._(int id) {
  static const primary = ColorToken._(0);
  static const danger = ColorToken._(8);
  // … fixed slots 0..17 in use, ids up to 31 reserved
  const ColorToken.generated(int id) : this._(id); // generated code only, guarded by a lint
}
enum SpaceToken { none, xs, sm, md, lg, xl, x2l, x3l }
enum RadiusToken { none, sm, md, lg, full }
enum TextToken { header1, header2, header3, body, label, caption }
extension type const ButtonVariant._(int id) { static const primary = ButtonVariant._(0); /* … */ }

final class StxTokens {               // one const instance per mode
  final List<Color> colors;           // [ColorToken.id] → O(1)
  final List<double> space;           // [SpaceToken.index]
  final List<double> radius;
  final List<double> breakpoints;
  final List<ResponsiveText> text;    // [TextToken.index]
  final List<ButtonSpec> button;      // [ButtonVariant.id]
}
```

A `Color` can never end up in a widget, because no `stx_ui` API accepts one.

### Performance

- **`StxTheme`** is a single `InheritedWidget`. It only rebuilds on a mode switch, and a lookup
  is O(1) followed by an array index.
- **`BreakpointScope`** is an `InheritedModel` above `MediaQuery.sizeOf`. It only notifies when
  the breakpoint enum changes, so not on every pixel of resize. Responsive text therefore only
  rebuilds when crossing a breakpoint.

## 5. Contract to code (phase 1)

### Input

The input is the **bundled** OpenAPI artifact of stratastax-contract (`build/openapi/*.yaml`, also
published on `https://docs.stratastax.dev/openapi/`, see §3 *Remote sources*), so all `$ref`s are
local (`#/components/...`). External refs give `STX-C003` with a hint.

Supported:

| OpenAPI | Dart |
|---|---|
| `string` / `format: uuid` | `Uuid` (extension type on `String`) |
| `string` / `format: date-time` | `DateTime` (UTC on encode) |
| `string` / `format: date` | `LocalDate` (stx_core) |
| `string` / `format: email` | `Email` |
| `integer` / `number` | `int` / `double` |
| string `enum` (component or inline) | Dart `enum` with `wire` and `decode` |
| `array` | `List<T>` (unmodifiable on decode) |
| `type: object` + `additionalProperties` | `Map<String, Object?>` or `Map<String, T>` |
| `$ref` to an object or enum | generated class / enum |
| `$ref` to an alias (`date_time`, `display_name`) | inline primitive, **with the constraints of the alias** |
| `allOf` (e.g. `paged_metadata` + items) | one class with all properties and `required` of all parts |
| `type: [x, 'null']`, `anyOf: [x, {type: 'null'}]` | nullable |
| optional + nullable in a **PATCH** body | `Patch<T>` (`Patch.unset()` / `Patch.value(v)` / `Patch.value(null)`) |
| request body `text/csv` (string schema) | `String` body with `requestContentType` |
| `anyOf`/`oneOf` with real alternatives | `STX-C002` |

### Output

```
lib/gen/contract/
  scopes.g.dart                    # enum Scope implements StxScope, across all contracts
  backends.g.dart                  # per backend an Endpoint subclass (PlatformEndpoint, …)
  platform_v1/
    platform_v1.g.dart             # barrel
    models.g.dart                  # barrel of models/
    models/create_match.g.dart     # CreateMatchV1, straight-line encode/decode, ==, hashCode
    validation/create_match.g.dart # CreateMatchV1Validation
    api/matches_api_v1.g.dart      # MatchesApiV1 + GetMatchParams, ListMatchesParams, …
  catalog_v1/…
```

Naming: schema `create_match` + `modelSuffix` → `CreateMatchV1`, tag `matches` + `apiSuffix` →
`MatchesApiV1`. Inline schemas get the name of their parent plus property
(`decide_match_edit.status` → `DecideMatchEditStatusV1`).

```dart
abstract final class CreateMatchV1Validation {
  static const gameId = UiFieldValidation(required: true, format: UiFormat.uuid);
  static const participants = UiFieldValidation(required: true);
  static const playsetId = UiFieldValidation(format: UiFormat.uuid);
}

/// Parameters of [MatchesApiV1.updateMatch].
final class UpdateMatchParams {
  const UpdateMatchParams({required this.matchId, required this.ifMatch});
  final Uuid matchId;
  final String ifMatch;   // header If-Match
}

abstract final class MatchesApiV1 {
  /// `PATCH /api/v1/matches/{matchId}` · any of `stx-engine:match-update`
  static const updateMatch = Endpoint<UpdateMatchParams, UpdateMatchV1, MatchV1>(
    operationId: 'updateMatch',
    method: HttpMethod.patch,
    path: PathTemplate(['api', 'v1', 'matches', '{matchId}']),
    security: Secured.scopes({Scope.matchUpdate}),
    encodePath: _updateMatchPath,
    encodeHeaders: _updateMatchHeaders,
    encodeBody: UpdateMatchV1.encode,
    decode: MatchV1.decode,
  );
}
```

- An operation without parameters has `NoParams`, without body `NoBody`, without response body
  `NoContent`. Parameters are a generated class per operation (not records), so optional query
  parameters can be omitted.
- An `Idempotency-Key` header is not a parameter but `idempotent: true`; the interceptor sets it.
- `stx scan --contracts` dumps the `ContractIR` as YAML.

### Security and scopes

- Only the `security` of the operation counts; the root-level `security` is ignored and an
  operation without its own `security` is `STX-C001`.
- `security: []` → `Secured.public()`, `bearerAuth: []` → `Secured.authenticated()`.
- Scopes of one operation are **alternatives** (any-of):
  `Secured.scopes(set).allows(...)` is true if the user has **one** of them.

The compiler generates a single `enum Scope implements StxScope` across all contracts. Scopes are
therefore typed, and a set of them is simply `const`: `Secured.scopes({Scope.matchCreate})`. The
claims of a token are converted once (`Scope.fromClaims` → `Set<Scope>`; unknown claims are
dropped). A page has a `ScopeRequirement`: one group per operation used, and every group must hit
at least one scope. See ADR-12 for why this is an enum set and not a bitset.

### Backends

Each contract belongs to a backend (`backends:` in stx.yaml). Per backend the compiler generates:

- in phase 1 an `Endpoint` subclass (`PlatformEndpoint`), which all operations of its contracts
  use;
- in phase 2 its own `StxClient` with its own base URL and interceptors, and a typed wrapper
  `extension type PlatformClient(StxClient http)` whose `send`/`fetch`/`submit`/`exchange` accept
  only a `PlatformEndpoint`.

`services.catalog.submit(MatchesApiV1.createMatch, …)` therefore does not compile. How a client
authenticates is `auth:` of its backend:

| `auth` | Token of `BearerAuthInterceptor` | Override |
|---|---|---|
| `none` | none | – |
| `oidc` (default with `security:`) | the user's `Session` | `AppConfig.access` (then no token) |
| `serviceAccount` | `ServiceAccountTokens`: client credentials of `serviceAccount: { clientId, scopes, issuer? }` (issuer: that of `security.oidc` by default, or `--dart-define=STX_<BACKEND>_ISSUER`), secret from `--dart-define=STX_<BACKEND>_CLIENT_SECRET` | `AppConfig.<backend>Tokens` |
| `token` | `StaticTokenSource` from `--dart-define=STX_<BACKEND>_TOKEN` | `AppConfig.<backend>Tokens` (e.g. a token from a backend for frontend) |

The tokens of a `serviceAccount` or `token` backend are independent of the session: they are there
before and after a login, and `start()` obtains them alongside the session (without waiting).

### HTTP (`stx_http`)

```dart
final result = await client.fetch(MatchesApiV1.getMatch, GetMatchParams(matchId: id));
switch (result) {
  case Ok(:final value): …
  case Err(error: Problem(status: 404)): …
  case Err(:final error): …
}

await client.submit(MatchesApiV1.createMatch, CreateMatchV1(...));          // no params
await client.send(MatchesApiV1.updateMatch, params: p, body: patch);        // both
final reply = await client.exchange(MatchesApiV1.getMatch, params: p, body: ()); // + status, ETag
```

- Every call returns a `Result<R, Problem>`; no exceptions cross the API boundary. An HTTP error
  becomes the `Problem` from the body (`problem_detail.yaml`), a network error
  `ProblemType.network`, a response that violates the contract `ProblemType.decoding` with the path
  (`participants[0].outcome`). This mapping lives in the client itself, not in an optional
  interceptor.
- An error body without a problem `type` (a proxy, another service) gets the type that goes with
  its status: a 404 is `notFound`, not `unknown`.
- The interceptor chain is built once. Order, outermost first:
  `LoggingInterceptor → BearerAuthInterceptor → IdempotencyKeyInterceptor → RetryInterceptor`.
- `LoggingInterceptor`: one line per request and response, `authorization` masked. Request
  bodies are never logged; for a failed response the start of the body is, so that a 404
  or 400 can be explained.
- `BearerAuthInterceptor(TokenSource)`: bearer only on endpoints that require authentication; on
  a 401 one refresh (shared between concurrent requests) and one retry. `stx_security`
  implements `TokenSource`.
- `IdempotencyKeyInterceptor`: a UUIDv7 on endpoints with `idempotent: true`; because it sits
  before the retry, every retry reuses the same key.
- `RetryInterceptor`: only `endpoint.retryable` (safe methods or an idempotency key), on
  network errors and 502/503/504, exponential backoff with jitter, `Retry-After` respected.
- Transports: `dart:io` (`IoTransport`) and `fetch` (`WebTransport`), chosen via conditional
  import. Both compile for dart2js and dart2wasm.

## 6. Consumer code

A consuming app contains:

- annotated command classes (`@UiRoute`, `@UiForm`, field annotations), the domain entities they
  use (`@DomainEntity`) and type converters (`@BuildTypeConverter`);
- data sources (`@UiDataSource`) and custom field widgets (`extends StxFieldWidget<T>`);
- `stx.yaml`, `stx.tokens.yaml` and `i18n/<locale>.yaml`. There is no text in code;
- a `main.dart` that calls `runStxApp(AppConfig.fromEnvironment(log: …))`, with base URLs and
  issuer coming from `--dart-define`.

For a complete example, see [`examples/match_tracker/lib`](../examples/match_tracker/lib).

```dart
@UiRoute('/matches/new')                            // embedded in /matches (see Overviews)
@UiForm(submit: MatchesApiV1.createMatch)
@UiRequires([Scope.ghostPlayerRead]) // ParticipantsField searches ghost players
@DomainEntity()
final class MatchCreateCommand {
  @UiFormOrder(10)
  @UiFieldDataSource(GameSearchSource)
  @UiFieldHint()
  final GameId gameId;

  @UiFormOrder(20)
  final DateTime playedAt;

  @UiFormOrder(30)
  @UiFieldWidget(ParticipantsField)
  @ContractProperty('participants')
  final List<Participant> players;

  @UiFormOrder(40)
  final bool editRequestsEnabled;

  const MatchCreateCommand({required this.gameId, required this.playedAt, required this.players, required this.editRequestsEnabled});
}
```

The link with the contract goes through **the operation**. `submit:` provides the body schema (and
with it mapping and validation), the response type, the scopes and the endpoint.

**Mapping.** Fields match by name; `@ContractProperty('x')` overrides that.

| Domain type | Contract type | Generated |
|---|---|---|
| primitive (`String`, `int`, `double`, `bool`, `DateTime`, `LocalDate`, `Uuid`, `Email`) | the same | `c.x` |
| `@BuildTypeConverter(Uuid) extension type GameId(Uuid value)` | `uuid` | `c.gameId.value` |
| generated contract enum or model (`ScoreTypeV1`) | the same | `c.scoreType` |
| `@DomainEntity` class | object schema | `ParticipantMapper.toContract(e)` in `mappers.g.dart` |
| `List<T>` | `array` | `[for (final e0 in c.players) …]` |

Domain fields that are nullable while the contract requires the value are an error
(`STX-U003`). So are required contract properties without a field (`STX-U001`). A field without
a contract property must have `@UiIgnore` (`STX-U002`).

**`@UiIgnore`.** The field is not in the form; the command gets the default from the
constructor. That default is sent if the contract has a property with that name. Without a
property it is UI-only data.

**Field kind.** This is derived from the type; `@UiFieldType` may refine it within the type.

| Type | Field | Widget |
|---|---|---|
| `String` | text (`textArea`, `password` via `@UiFieldType`) | `StxFormText` |
| `int` / `double` | number | `StxFormNumber<T>` |
| `bool` | checkbox | `StxFormCheckbox` |
| `DateTime` / `LocalDate` | dateTime / date | `StxFormDateTime` / `StxFormDate` |
| Dart enum | select, options = `values`, labels = `enum.<Enum>.<value>` | `StxFormSelect<T>` |
| with `@UiFieldDataSource` | autocomplete | `StxAutocomplete<T>` |
| with `@UiFieldWidget(W)` | custom (`W extends StxFieldWidget<T>`, `T` checked) | `W` |

## 7. Generated app code (phase 2)

The compiler reads `lib/**.dart` with the `analyzer` (resolved, against the output of phase 1),
builds a `UiIR`, merges it with `ContractIR` and `I18nIR` into an `AppPlan`, validates, and
renders `lib/gen/app/`:

| File | Contents |
|---|---|
| `pages/<view>.page.g.dart` | For a `@UiListPage`: `<View>Page` with its `requires`, a `StxListController` with the filters and sorts, the columns and `StxListScaffold` |
| `forms/<command>.form.g.dart` | `<Command>Form extends StxFormController`: a `StxField` per field, merged `UiFieldValidation` constants, a static validator per field, `toCommand()`, `toContract()`, `contractFields` (to show server errors at the right field) |
| `pages/<command>.page.g.dart` | `<Command>Page` with `static const requires = ScopeRequirement([...])`, `StxGuard`, `StxFormScaffold` and the field widgets |
| `mappers.g.dart` | `<Entity>Mapper.toContract` for nested `@DomainEntity` classes |
| `routes.g.dart` | `sealed class AppRoute`, `parseRoute`/`routeSegments`/`buildRoute`/`requiredScopes` as exhaustive `switch`es, `navItems`, `const appRoutes` |
| `config.g.dart` | `AppConfig`: per backend a `StxBackend` (base URL via `--dart-define=STX_<BACKEND>_BASE_URL`, extra interceptors), access, OIDC, transport, locale store |
| `services.g.dart` | `AppServices`: per backend a typed client, the session, a `StxEndpointSource` per `@UiDataSource`, the shared `searchCache` and a `StxSearchService` per `@UiListPage`; plus the `<Backend>Client` wrappers |
| `app.g.dart` | `runStxApp`, `AppRoot` on `StxApp` (= `WidgetsApp.router`) with router, shell, tokens, translations and access |

Key excerpt from `match_create_command.form.g.dart`:

```dart
@override

  var ok = true;

```

The page requirement is derived, not declared:

```dart
/// stx-engine:match-create & stx-engine:ghost-player-read & stx-engine:game-read
static const requires = ScopeRequirement([
  {Scope.matchCreate},     // submit: createMatch
  {Scope.ghostPlayerRead}, // @UiRequires
  {Scope.gameRead},        // GameSearchSource: getGameSuggestions

```

Runtime behavior of a form (`StxFormController`):
- after success: back to the previous page, or (without a previous page) a confirmation and an
  empty form (`resetFields()` is generated);
- server errors with a known backend code (`OUT_OF_RANGE`, `NOT_FOUND`, …) get a translated
  text at the field, unknown codes remain visible;
- validation only on the first submit, after that live on every change;
- no request if local validation fails;
- `violations` from a validation `Problem` from the server reach the right field via
  `contractFields` (`FieldError.server(code)`), the rest as a banner (`stx.problem.*`).

### Overviews (`@UiListPage`)

An overview is declared like a form: a `@DomainEntity` class whose fields are paths into the
item schema of a list operation. The search annotations mirror `@SearchFilter` / `@SearchSort`
of stratastax-entity on the server:

```dart
@UiRoute('/matches', nav: UiNav.primary, home: true)
@UiListPage(
  list: MatchesApiV1.listMatches,
  count: MatchesApiV1.countMatches,                  // optional: "1–20 of 45" instead of "Page 1"
  panel: UiSearchPanel(layout: UiPanelLayout.side),  // auto (default) | side | top, start | end
  cache: UiCache(mode: UiCacheMode.staleWhileRevalidate, ttlSeconds: 60),
  actions: [UiAction(MatchCreateCommand)],           // a "New match" button next to the title
)
@DomainEntity()
final class MatchOverview {
  @UiColumn(order: 10, primary: true, flex: 2)
  @ContractProperty('game.displayName')              // a path; nullable steps need a nullable field
  @SearchText(alias: 'gameName')                     // the search box: =ilike= on every such field, OR
  final String gameName;

  @ContractProperty('game.id')
  @SearchFilter(source: GameSearchSource)            // filter only: pick a game, gameId==…
  final GameId gameId;

  @UiColumn(order: 20)
  @SearchFilter()                                    // date-time: from–to (whole local days)
  @SearchSort(direction: SearchDirection.desc, initial: true)
  final DateTime playedAt;
  …
}
```

**Embedded pages.** A route is embedded in the route with the longest path that is a segment
prefix of its own: `/matches/new` in `/matches`. It is left out of the navigation (no `nav:`) and
opened with a `UiAction` on the overview: a `StxRouteButton` next to the title, labelled with the
title of that page and hidden without its scopes. The button pushes the page, so after saving
(`UiNavigate.back`) the overview is on top again and loads again, without the cache entries the
form invalidated. While the embedded page is open, the navigation keeps its overview active
(`StxNavigator.isActive`). A deep link opens the embedded page alone (the overview would start
requests nobody sees); back, the system back button included, then goes to the overview
(`parentRoute` in `routes.g.dart`).

The list operation must have the four query parameters of stratastax-contract (`limit`,
`cursor`, `filter`, `sort`) and return `paged_metadata` with `items`. The count operation takes
only `filter` and returns `{count}`. Filter and sort names default to the flattened path
(`game.id` → `gameId`), the naming rule of the contract; `alias` overrides it (`name` for
`displayName`).

The input of a filter follows from the contract type of the path:

| Type | Input | RSQL |
|---|---|---|
| string | text | `field=ilike="%text%"` (with `%`, `_`, `\` escaped) |
| enum | choice chips (`enum.<Type>.<value>` labels) | `field=in=(A,B)` |
| boolean | any / yes / no | `field==true` |
| integer, number | from–to | `field=ge=1;field=le=4` |
| date-time, date | from–to | `field=ge=<from>;field=lt=<day after to>` |
| with `source:` | autocomplete | `field==<value>` |

Filters are combined with `;`, the search text first. A filter or sort change goes back to the
first page (debounced for typing); the total is only fetched again when the filter changed.
With a cursor only `cursor` and `limit` are sent: the engine's cursor carries the criteria it was
issued for, so they cannot disagree with it. The client always sends a sort: the initial one,
or the first `@SearchSort`.

**Which fields are allowed.** The contract lists them only in prose (the operation's
`description`), so the annotations are the client's own declaration, checked against the item
schema. When an operation has `x-stx-search: {filter: [...], sort: [...]}`, the compiler also
checks every alias against it (`STX-U010`); without it the server rejects an unknown field
with 400. Emitting `x-stx-search` from the `@Search*` annotations in stratastax-codegen is the
follow-up that makes this a build error everywhere.

**Layout.** `StxListScaffold` reads the breakpoint: with `layout: auto` the filters are a side
panel from `lg`, a bar above the results from `collapseBelow` (default `md`), and a "Filters (n)"
button with a full-screen sheet below it; `side` and `top` keep their shape down to
`collapseBelow`. Results are a table (sortable headers) from `md` and cards below; active
filters show as removable chips. Styling comes from `components.table`, `.chip` and `.panel`.

**The service and the cache.** Pages never call a client: a generated `StxSearchService` per
overview talks to the list and count endpoints, through `StxSearchCache`, one per
`AppServices`. List endpoints send no `ETag` or `Cache-Control`, so caching is a client policy:
`none`, `memory` (reuse until the ttl) or `staleWhileRevalidate` (show the old page at once,
replace it when the fresh one arrives); stx.yaml `search.cache` sets the default, `@UiListPage`
per page. The ttl is capped below the 24-hour lifetime of engine cursors, errors are not cached,
and concurrent requests for one page share a call. Entries carry the contract tag of the
endpoint: a successful generated form calls `invalidateTag` for the tag of its operation
(`createMatch` → `matches`).

Routing: `StxRouter.config(appRoutes, shell: …)` provides a `RouterConfig` for
`WidgetsApp.router` (Navigator 2.0, page stack, deep links). Navigation is typed:
`StxRouter.of<AppRoute>(context).go(const MatchCreateRoute())`.

## 8. Security

| Aspect | Design |
|---|---|
| Source | `security: - bearerAuth: [stx-engine:…]` per operation, parsed into `SecurityIR`. `Undeclared` gives a build error. |
| Derivation | The scopes of a page are the union of all endpoints the page touches: submit, datasources and loaders. `@UiRequires(...)` may add scopes, never remove them. |
| Guard | Every generated page is in a `StxGuard(requires: ScopeRequirement)`: one group per operation the page uses, each group asks for one of its scopes. Not logged in → `StxSignIn` (one button per login option, plus the reason if the previous attempt failed); missing scope → `stx.access.forbidden`. The form is then not built. A separate login route is not needed: the guard is the redirect, and after the callback the app returns to the route where the login began. |
| Navigation | `StxAppShell` only shows `navItems` whose `ScopeRequirement` is satisfied. |
| Login | `stx_security.Session`: OIDC Authorization Code with PKCE (S256) against Keycloak, `state` check, return to the original route. Social login: `security.social` in stx.yaml becomes `AppServices.loginOptions` (`StxLoginOption(idpHint: 'google')` → `kc_idp_hint`). Logout via the end-session endpoint with `id_token_hint`. |
| Tokens | The access token lives in memory only. The refresh token sits behind `SecureStore` (web: sessionStorage, so a reload restores the session but a new tab does not; mobile: adapter package). Refresh is single-flight and happens 30 s before expiry; a rejected refresh logs out, a network error does not. Roles come from `realm_access.roles`, `resource_access.*.roles`, `scope` and `groups` (configurable via `roleClaims`) and become a `Set<Scope>` via `Scope.fromClaims`. The `LoggingInterceptor` redacts `authorization`, and tokens are never printed. |
| Runtime cost | The claims are converted to a `Set<Scope>` once per token. A check is then a few set lookups. |
| Wiring | With `security:` the compiler generates an `AppServices` with `Session`, `BearerAuthInterceptor(session)` on the clients of `auth: oidc` backends, and `SessionAccess` (implements `StxAccess` and `StxAuth`); `runStxApp` waits for `services.start()` (finish the callback or restore the session). `AppConfig.access` overrides the session, e.g. `StaticAccess` in tests and previews. Without `security:`, `access` remains required. |
| Shell | `StxAppShell` shows the user name (`Msg.data`) and `stx.session.signOut`. |
| Service accounts | A backend with `auth: serviceAccount` (§5 *Backends*) gets its own tokens with the client credentials grant, kept in memory, single-flight, renewed 30 s before expiry; a refused grant gives no token, an unreachable identity provider keeps the current one. **A client secret in an app is not a secret**: it can be extracted from the binary or the JavaScript. So a service account is only for data that is public anyway (the published translations): one Keycloak client per app, with read scopes only (`stx-i18n:bundle-read`). On the web, prefer `auth: token` with a token from a backend for frontend. |

## 9. i18n

| Part | How |
|---|---|
| Sources | `i18n/<locale>.yaml` of the app + framework texts from `stx_i18n/lib/i18n/stx.<locale>.yaml` (en, nl; other languages fall back to en) |
| Keys | The key name is the identity (`MsgKey('stx.action.save')`); framework keys are in `StxKeys` (a test guards that every key from `stx.en.yaml` has a constant there), app keys in `keys.g.dart` |
| Messages | ICU subset: text, `{x}`, `{n, number[, integer\|percent]}`, `{d, date[, short\|medium\|long\|full]}`, `{d, time[, short\|medium]}`, `plural` (`=N`, CLDR categories, `#`), `select`; quoting with `'` |
| Compilation | At build time to Dart: plural/select become `switch` expressions, `#` and `number` go through the locale formats; nothing is parsed at runtime |
| Types | Factories are typed by usage: `playersCount({required num count})`, `date` → `DateTime`, `select` → `String`; locales must use the same placeholders (`STX-I002`) |
| CLDR | Bundled data for en, nl, de, fr, es: cardinal plural rules, month and day names, date/time patterns (compiled to interpolation), first day of the week, decimal and grouping separator, input format |
| Date fields | Typed in the numeric order of the locale (`31-12-2026 18:30`, `12/31/2026 18:30`), example as hint, calendar with locale names and first weekday |
| Sync | `stx i18n sync` adds the keys that generated pages need, preserving formatting and comments: in the base locale with a suggestion (short contract `description`, otherwise the humanized name), in the other locales the base text plus a list of what needs translating |
| Lint | `stx_no_string_in_ui`: a string literal in `Msg.data(…)` or `Text(…)` in app code |
| Loading | `keys.g.dart`, `messages_<locale>.g.dart` (messages + `_Formats<Locale>`), `locales.g.dart` with deferred non-base locales |
| From a backend | `i18n.remote`: the published texts of the i18n CMS are laid over the YAML texts at runtime, for existing keys only (see *Translations from a backend*) |

### Sources

| Source | Contents | Owner |
|---|---|---|
| `stx_i18n` (defaults) | `stx.*`: validation, generic actions, no access, loading, empty state (en, nl) | framework |
| `i18n/<locale>.yaml` | All screen texts and shared `common.*`. Source of truth of the app: its keys and placeholders. | consumer |
| i18n backend (`i18n.remote`) | Published translations of existing keys, from the CMS | content editors |

Precedence, highest first: the backend (fetched in this run) > the cached bundle > the app's YAML >
the framework's YAML > the key name. An app overrides a framework text by translating the same
`stx.*` key; the backend can override both.

### `stx i18n sync`

`stx i18n sync` runs explicitly, never during `build`.
1. Missing keys are added to the base locale with a seed and `# TODO`. The seed is the
   OpenAPI `title` or the `description` of the linked property, and otherwise the humanized
   field name (`playedAt` becomes "Played at").
2. Missing keys are added to the other locales with the base text, so the build passes, and are
   listed so they can be translated.

`stx build` fails on a missing base key. For other locales that depends on
`missing: error|fallback`.

### Keys by convention

| Source | Key |
|---|---|
| `@UiRoute` / `@UiForm` on `MatchCreateCommand` | `matchCreateCommand.title` (optionally `.description`) |
| field `gameId` | `matchCreateCommand.gameId.label` |
| `@UiFieldHint()` / `@UiFieldHelp()` | `matchCreateCommand.gameId.hint` / `.help` (opt-in, and then required) |
| `@UiForm(submit:)` | `matchCreateCommand.submit`, with fallback `stx.action.save` |
| contract enum in a select | `enum.ScoreType.numeric`, … (required as soon as the enum is in the UI) |
| `Problem.code` (enum in the contract) | `problem.<code>`, with fallback `stx.problem.generic` |
| `FieldError.*` | `stx.validation.*` |

Reuse is explicit via `@UiFieldLabel(MsgCommon.players)`. That works because
`lib/gen/i18n/keys.g.dart` is already rendered in phase 1.

### Format: ICU MessageFormat subset, compiled

```yaml
matchCreateCommand:
  playersSelected: '{count, plural, =0{No players yet} one{1 player selected} other{# players selected}}'
  playedOn: 'Played on {date, date, medium}'
```

Supported: plain text, `{x}` (`String`), `plural` (`int`), `select` (enum or `String`), `date`
(`DateTime`) and `number` (`num`). Placeholders and their types must be the same in every locale,
otherwise a build error follows.

### Generated

| File | Contents |
|---|---|
| `keys.g.dart` | `MsgCommon`, `MsgMatchCreateCommand`, … with `static const MsgKey` (usable in annotations), and typed factories for messages with parameters |
| `messages_<locale>.g.dart` | Const `Map<String, String>` (key name → text, framework and app texts) plus a `switch` on the key name for messages with parameters, with plural via the generated CLDR rule |
| `locales.g.dart` | `supportedLocales`, `loadMessages`. Non-base locales are `deferred`. |
| `arguments.g.dart` | `messageArguments`: per key with placeholders their names and `ArgType`s, in the order of `MsgArgs.args`; `StxMessages.arguments` of every locale |
| `app/translations.g.dart` | With `i18n.remote`: `RemoteTranslations`, the `TranslationSource` on `getBundle` of the i18n contract |

### Runtime

- `Msg` is a sealed type with three forms:
  - `MsgKey('matchCreateCommand.gameId.label')`: the key name is the identity. A missing
    text shows the name
  - `MsgArgs(key, [values])`: text with parameters, positional in the order of the
    placeholders; built by the generated factories (`MsgMatchCreateCommand.playersCount(count: 2)`)
  - `Msg.data(String)`: for user data. The lint forbids a string literal here.
- All `stx_ui` APIs accept `Msg`, never `String`. The lint `stx_no_string_in_ui` enforces this.
- Plural rules and date/number patterns are generated by the compiler from a bundled CLDR subset,
  only for the configured locales. There is no `intl` at runtime.
- `StxLocaleScope` manages the current locale and persists the choice via `LocaleStore`.
- Contract enums get an extension `ScoreTypeV1.numeric.msg`.

### Translations from a backend

```yaml
backends:
  i18n:
    baseUrl: https://i18n.stratastax.dev
    auth: serviceAccount
    serviceAccount: { clientId: match-tracker-i18n, scopes: [stx-i18n:bundle-read] }
i18n:
  remote: { backend: i18n, application: match-tracker }   # spec: the i18n contract (default: docs.stratastax.dev)
```

`i18n.remote` adds the contract `stratastax.i18n.api-v1.yaml` as `stxI18nV1` for that backend
(fetched and locked like any remote source, §3), and generates `RemoteTranslations` on its
`getBundle`. `AppServices.translations` goes to `StxApp` and `StxLocaleScope`:

1. A locale loads its compiled messages as before. When `AppConfig.translationCache` has a
   bundle for it, that is laid over them at once. The first frame never waits for the network.
2. In the background the bundle is fetched with `If-None-Match` (the ETag of the cached
   bundle): `304` keeps what is shown, `404` (nothing published) keeps the YAML texts, a failure
   is reported to `AppConfig.onTranslationIssue` and keeps the texts.
3. A new bundle is cached and swapped in, unless the locale changed meanwhile.
   `StxLocaleScope.refresh(context)` fetches again, e.g. when the app resumes.

`OverlayMessages` lays a bundle over the compiled messages and validates every text when it is
built:

| Text from the backend | Result |
|---|---|
| A key the app does not have | Left out (`unknownKey`): the backend can only translate existing keys |
| Invalid ICU | Left out (`syntax`) |
| A placeholder the key does not have, or of another type (`StxMessages.arguments`, compatible as between locales) | Left out (`arguments`) |
| A plain text for a key without placeholders | Used as is |
| An ICU text for a key with placeholders | Parsed once, then interpreted per call by `formatIcu` (stx_i18n) with the locale's formats |

The interpreter has the semantics of the compiled code (`#` and `number` through the locale
formats, exact plural matches before the CLDR category, `other` as the fallback), so a text means
the same whether it comes from YAML or from the CMS. Formats, plural rules and every other key
stay compiled. A broken translation never breaks a screen; it only falls back to the YAML text.

## 10. Limitations

- **Pages.** Forms and overviews are generated; there are no detail pages yet, so a row of an
  overview does not open anything, and route parameters are not supported (`STX-U006`).
- **Overviews.** List operations with path parameters (`/games/{gameId}/expansions`) are not
  supported; columns show single values (no lists); one sort key at a time; no free choice of
  operator per filter. Without `x-stx-search` in the contract a wrong filter name is a 400 at
  runtime, not a build error.
- **Contract.** `anyOf`/`oneOf` with real alternatives (so no discriminator support), non-string
  enums, and request content other than JSON or a string schema are rejected (`STX-C002`).
- **Auth.** The OIDC login is a web redirect flow. There are no mobile auth redirects, and the
  mobile `SecureStore` needs an adapter package.
- **i18n.** No ARB/XLIFF export or import, no RTL, and CLDR data only for en, nl, de, fr and es.
- **Style.** No animation tokens.

## 13. Decisions (ADR)

### ADR-1: compiler as a Dart CLI with `analyzer`

**Alternatives:**
- a Kotlin/Gradle generator
- a hybrid setup (contract in Kotlin, UI in Dart)
- build_runner as the driver

**Choice:** a Dart CLI.
- Resolved Dart types are needed for type safety: const `Endpoint` references and generic
  checks on custom fields.
- No JVM is needed in the Flutter repo.
- Phase 2 must resolve against the output of phase 1. That order is hard to guarantee with
  build_runner, and slow.
- `AnalysisContextCollection` with a custom cache is faster and more predictable. A thin
  build_runner Builder can still be added later as a wrapper.

### ADR-2: own OpenAPI generator instead of dart-dio/built_value

**Why:**
- The dart-dio/built_value chain needs post-processing fixes.
- It generates built_value boilerplate.
- It provides no validation or scope information, which we need in one IR anyway.

An own generator delivers immutable classes, sealed types, extension types and straight-line
codecs, and shares the `ContractIR` with the UI phase.

### ADR-3: no material or cupertino, tokens as index extension types

- Full control over the styling.
- No chance of per-widget colors.
- A smaller bundle.

Tokens as `int`-index extension types are zero-cost and type-safe, and a lookup is an
array index. The price: more own widgets, notably text input (`EditableText` with own
selection controls) and overlays.

### ADR-4: i18n with YAML and ICU, compiled, with convention keys

**Alternative:** `gen_l10n` with ARB.

**Why not:**
- gen_l10n pulls in `flutter_localizations` with material localizations
- the keys cannot be linked to annotations
- ICU is parsed at runtime

With own YAML, keys arise from the convention, the build checks that they are complete,
messages are ready as const tables, and locales can be loaded deferred.

### ADR-5: compile-time DI and router, no get_it or go_router

- `AppServices` and `AppRoute` are fully generated and can be checked exhaustively by the
  Dart compiler.
- There is no service-locator lookup and no string routing at runtime.
- Only `flutter/widgets` is needed.

### ADR-6: fixed token slots with `extend`, defaults in stx_style

The widgets in `stx_ui` are compiled before an app YAML exists. That is why `stx_style` fixes a
schema of slots; the app fills in values and extends via `extend`. Defaults live as YAML in
`stx_style` and the compiler finds them via `package_config.json`, so that defaults and
runtime types always come from the same version.

### ADR-7: converters via the representation type

Constant evaluation erases extension types: `@BuildTypeConverter(Uuid)` yields `String`. The
compiler therefore reads the type of the representation field (`GameId(Uuid value)` → `Uuid`); the
annotation only marks *that* the type is a converter.

### ADR-8: one dependency resolution with the Flutter SDK

`flutter_test` pins `test_api`, which makes the compiler use `analyzer` 12. A consumer app
has `stx_compiler` as a dev dependency in the same resolution, so the compiler follows the pins of
the Flutter SDK instead of the newest `analyzer`.

### ADR-9: CLDR bundled and compiled, no `intl`

`intl` would interpret patterns and ICU messages at runtime and does not depend on the
annotation pipeline. The compiler bundles only the CLDR data that stx uses (plural rules,
names, patterns, number symbols) for a fixed set of languages and compiles them per locale to code;
adding a language is an entry in `cldr.dart` and a test. Date input uses the numeric
order of the locale with a four-digit year and 24-hour time: unambiguous to type, even where the
display (`6:05 PM`) is not.

### ADR-10: lints for app code only, via a workspace plugin

Analyzer plugins may only live in the root of a workspace, so the rules also see the
framework packages. Those implement the tokens and may use `Color` and `EdgeInsets`; the rules
therefore only apply to `lib/` outside `lib/gen` and outside `package:stx_*`. Tests and tools may
use literals.

### ADR-11: the guard is the login redirect; tokens per tab

There is no separate login route: `StxGuard` shows `StxSignIn` in place of the page, and the login
remembers the URL where it began. That prevents a redirect loop and a route that is outside the
contract. The refresh token is in sessionStorage, not in localStorage: an XSS then cannot get it
from other tabs or after the browser is closed, at the cost of logging in again per tab. Whoever
wants to stay logged in longer passes their own `SecureStore`. The client does not verify the
JWT signature; it only reads the claims to adapt the UI, the API verifies.

### ADR-12: scopes as a set of enums, i18n by key name, `AppServices`

- **Scopes are an enum set, not a bitset.** A bitset (`ScopeSet` over 32-bit words) would make a
  check an AND, but a check only runs a few times per rebuild, so it gives no measurable gain and
  costs readability (`ScopeSet([0x02000000])` in generated code). An `enum Scope implements
  StxScope` is just as type-safe, and `const {Scope.matchCreate}` is const too.
- **The key name is the i18n identity, not an int index.** With int indices, framework keys sit
  at fixed positions 0..n and app keys after them, so a new framework key shifts all app ids: an
  app that updates stx_i18n without regenerating would silently show wrong texts. The key name is
  robust across package versions and readable when debugging, for the price of a hash lookup.
- **`AppConfig` and `AppServices`.** `AppConfig` is what differs per environment (the input),
  `AppServices` is what is built from it.
- **One client per backend.** A single client for the whole app is too limited; see §5
  *Backends*.

### ADR-13: remote sources with a lock file, not copies or a package

The contracts and the brand tokens are owned by other repositories and published on
docs.stratastax.dev. Copying them into every app goes stale silently. A Dart package per contract
would need a release for every contract change. Fetching on every build would make builds depend
on the network, and different from day to day.

So stx fetches them once into `.dart_tool` and pins their sha256 in `stx.lock`. It works like
`pubspec.lock`: a build reads the same bytes until someone runs `stx sources update`, which shows
what changed. The mechanism is generic (contracts and tokens use the same resolver), and the
frontends only ever read a local file. `stx.local.yaml` points an alias at a checkout for
unpublished changes. Only an `api-vN` file that changes backwards-compatibly is updated in place
(the versioning rule of stratastax-contract); a breaking change is a new file, so a new reference.

### ADR-14: translations from a backend overlay the compiled ones, interpreted at runtime

Content editors want to change texts without a release; the app wants compiled, typed messages
that are complete at every start. The YAML files therefore stay the source of keys, placeholders
and the fallback, and the backend can only override texts of existing keys. Its texts cannot be
compiled, so they are parsed and checked against the generated placeholder table once, and
interpreted with the same semantics as the compiled code (the parser is shared through
`stx_icu`). The overlay never blocks: compiled (or cached) texts first, the backend's when they
arrive.

The consumer reads published bundles with a service account, not with the user's session: the
texts are the same for everyone, are needed before the login, and must not depend on the user's
roles. Because a client secret in an app is not a secret, the service account only has the read
scope of published bundles; the CMS uses the same contract with user auth for administrators.

### ADR-15: overviews declared on the domain model, checked against `x-stx-search` when present

The server already declares what is filterable and sortable, with `@SearchFilter` and
`@SearchSort` on its entities, but the contract carries that only as prose. Parsing prose is
fragile, and waiting for a machine-readable contract would block the client. Overviews are
therefore declared with the same annotations on a client-side domain class, checked against the
item schema (paths, types, operators per type), and the compiler checks them against an optional
`x-stx-search` extension per operation, which stratastax-codegen can emit from the server
annotations later. The UI can only narrow what the server allows, as with validation.

Pages talk to a generated `StxSearchService`, not to a client, so paging, totals and caching are
one place, and tests can replace the source. List endpoints have no HTTP caching, so the cache
is a client policy with tags per contract resource; the generated forms drop the tags they make
stale. Paging is a pager on the cursors (`nextCursor`, `prevCursor`) and the `/count` endpoints,
not infinite scroll: positions and totals stay meaningful, and it works the same on every screen.
